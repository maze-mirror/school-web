## H002：行统计解析提示的准确性

状态：2026-11-04—05 用户授权恢复诊断展示，暂不解决解析器兼容性。新扫描已提供 JS／TS 与 Java 未识别位置的行列范围，编码／读取失败按文件显示原因；函数诊断仍按 H001 隐藏。

截图中的 TypeScript 提示“存在未完整识别的语法或未闭合内容；行统计基于已识别区域，请结合源码复核。”来自行统计解析器，不能据此判断文件源码有错。

本地复查发现，`modern-languages.ts` 中以下合法写法会使当前 `@lezer/javascript` 1.5.4 的 TypeScript 模式产生一个错误恢复节点，而 TypeScript 编译器解析未报告语法错误：

```ts
for (let line = first; line <= last; line++) flags[line]! |= kind
```

这里的 `!` 是 TypeScript 非空断言。提示反映当前解析器的识别局限；没有证明该文件的行数已经算错。隐藏页面说明不表示解析器问题已修复。

2026-11-04 复核与用户反馈：11 行样例中的 `flags[line]! |= kind` 会触发该通用提示；将该行改为 `flags[line] = (flags[line] ?? 0) | kind` 后提示消失，两组均为 8 代码行、2 纯注释行、1 空行。开发侧调用当前分析器核对后，用户在页面重现了相同现象。这说明该样例暴露了解析器对合法写法的识别局限，但此例行分类未变化，不能据此推广到所有解析恢复情况。

用户进一步要求诊断明确指出位置，不能只提示检查源码。后续诊断应包含文件路径、未识别区域的行列／范围，并说明已知原因；解析恢复位置只能标为“未识别位置／附近”，不能直接断言是源码错误或真正根因。已知解析器局限应明确说明；是否影响行数需按具体样例验证，未知时不承诺无影响。定位诊断现已实现；旧历史通用提示仅说明当时未保存位置，不重新解析历史或虚构行列。

后续待确定：如何改进这类语法的支持、评估更多写法受影响的指标，以及进一步区分真实未闭合内容与解析器不支持的合法语法。当前只补定位和审慎说明，继续使用现有解析器，不将“轻量级”当成所有告警的已证实根因。旧 Python 提示也需按具体文本判断，不能一概当作同一原因。
